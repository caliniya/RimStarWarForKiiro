## 修复「小人不去装载 / 无法手动命令装载」

用户现象：点「组装运载火箭」进入装载中，AI 不派活，右键发射台也没有「装载」选项。

排查路径（有效，值得复用）：
1. 看日志 —— 启动参数有 `-savedatafolder=E:\data\rim`；
   RimWorld 的 Log 输出实际落在 `C:\Users\yiyi\AppData\LocalLow\Ludeon Studios\RimWorld by Ludeon Studios\Player.log`。
   日志里只有 `[StarWarKiiro] 模组代码已加载!`，**没有任何 Def 报错** → 排除 Def 加载失败。
2. 对比 `E:\app\rimworld\RimWorld16\Mods\StarWarKiiro` 与工程产物的时间戳 → 排除「跑的是旧副本」。

根因：`WorkGiver_LoadLaunchPad.JobOnThing` 里 `pawn.CanReserve(pad, 1, 8)`，
第二个参数是 **stackCount** 而不是 maxPawns。发射台是非堆叠建筑（stackCount 恒为 1），
预留 8 个 → `ReservationManager` 判定「要求数量 > 实际存在数量」→ **CanReserve 永远 false**
→ WorkGiver 恒返回 null → 自动派活和手动指令同时消失。
`TryMakePreToilReservations` 里 `pawn.Reserve(pad, job, 1, 8, ...)` 同病。

改法：
- `pawn.CanReserve(pad)`、`pawn.Reserve(pad, job, 1, -1, null, errorOnFailed)`（非堆叠物一律用默认 stackCount）
- 放弃「8 人并发装载」，改成一次一人（原注释写的并发其实是错的，maxPawns 写的是 1）
- 发射台 `GetInspectString` 新增诊断：缺的物资在地图上不存在时标注「（地图上找不到）」，
  配合新增的 `IngredientOnMap(ThingDef)`

已 `dotnet build` 通过并用 `build.ps1` 部署到 `E:\app\rimworld\RimWorld16\Mods\StarWarKiiro`（18:54，游戏未运行）。

## 用户偏好：发射台/控制台不要材质前缀
用户要求火箭发射台、火箭控制台像「高级研究台」一样不显示「钢铁」之类的材质前缀。
做法是删掉 ThingDef 里的 `<stuffCategories>` + `<costStuffCount>`，只保留固定 `<costList>`。
（MadeFromStuff 由 `!stuffCategories.NullOrEmpty()` 决定，只要有 stuffCategories 就会带材质前缀）
已改两个 def 并部署（20:56）。

用户随后确认「都删掉」，`StarWarKiiro_AdvancedResearchBench` 的 stuffCategories + costStuffCount 一并删除。
现在 Buildings_StarWarKiiro.xml 里三个建筑全部是纯固定 `<costList>`，均不带材质前缀。已部署（21:04）。

## 项目约定：本 Mod 的建筑一律不做材质选择
所有 ThingDef 不写 `<stuffCategories>` / `<costStuffCount>`，只用固定 `<costList>`。
新增建筑时照此办理。（判断依据：MadeFromStuff = !stuffCategories.NullOrEmpty()）
